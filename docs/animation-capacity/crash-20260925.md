## Important Scope Limit

The observed direct cause is insufficient temporary allocator space during
animation-load vector growth. It is not evidence for a 107 MB file-byte ceiling,
physical RAM exhaustion, or a universal 5,395-animation limit.

The default budget at module RVA 0x3B445F8 is **0x80000 (512 KiB)** in both disk
and captured memory, while this region is **0x20000 (128 KiB)**. Initializer
0x1EBC820 checks a thread-specific size before falling back to that default.
Setter 0x1EBCBA0 stores a requested size in thread-local state. Its scanned call
sites include 0x1ED9155 and 0x1F3C583, but the upstream source of the failing
thread's budget still needs verification.

Changing only the default may not affect this thread. Never bypass the null
check or fatal store: neither supplies missing storage. Any patch must ensure
the backing allocation and derived bounds grow together, preserve already
larger budgets, and account for per-thread memory cost and initialization time.
At this diagnostic checkpoint no replacement DLL was implemented. Subsequent
constructor tracing and experimental implementation evidence are recorded in
thread-budget-research.md and build.md; they do not turn this original capture
into a successful post-patch game run.
